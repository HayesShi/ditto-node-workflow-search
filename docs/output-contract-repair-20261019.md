# MATH 输出与 Automation 参数分类修复

工程提交：`3970bd5`。独立分支：`codex/math-engineering-repair`。

本轮解决输出协议和错误分类问题。检查节点可能判断错、修订节点可能把正确答案改错，这些仍是流程真实表现，不能通过工程兜底自动换回旧答案。96.64% 来自旧的直接生成流程；78.15% 来自旧候选的另一工程协议，二者不是单因素代码对照。

## 最终改动

1. **对齐基线最终答案格式。** 固定 MFlow `437040f17a17cbf430f3f41227ca64c576cf1056` 的 `src/prompts.ts` 本来要求数学最终答案使用 LaTeX boxed；`src/aflow-seed.ts` 的 agent/review/integrate 也有该要求。Ditto 现在将同一条格式要求传递给数学输出节点，并明确 revise 必须在 revisedResult.content 中交付完整修订解答，评估意见不是交付答案。原评分器、数据集、工具能力、token 上限和候选节点组织不变。此格式要求不作用于 Automation 或纯格式修复请求。
2. **保守修复 JSON 传输语法。** 只处理完整根对象之后多余的闭合花括号、字符串中非法反斜杠转义，以及原先已支持的 Markdown 包装。必须继续通过原 Ditto 节点字段校验；第二个对象、尾随正文、缺少闭合内容及缺失必需字段均不能静默接收。原响应保留在 provider 日志，修复事件记录变换种类和原内容 SHA-256。
3. **格式修复不能代替解题。** 不能本地处理的格式问题仍最多三次模型响应。修复请求只含第一份原始输出及字段要求，不再带原题和目标解答。已采用 MFlow 的 FORMAT_PROMPT，并增加内容保持校验：不能改既有答案、评估结论和问题文本，也不能凭空补写原输出没有的答案。修复始终基于第一份输出，避免多次修复逐渐改变含义。完整收到的 length 响应仍只消费一次，不继续生成以追求更好答案。
4. **Trello 入参错误不再污染环境状态。** 按 api_search 的公开接口约定，Trello 添加标签的 body 必须编码为对象。标量字符串、数组、布尔值、数字、字符串形式的 null 在进入官方路由前成为 INVALID_TOOL_ARGUMENTS 观察；模型可在同一个任务世界改正。真正的 bridge 错误继续使任务无效，不会把所有 TypeError 当业务异常，不改官方工具实现或评分断言。

没有固定增加终结节点、验证分支或工具循环，没有依据参考答案选择输出，没有事后补写 boxed 答案，也没有在修订失败时自动回退 solver。
