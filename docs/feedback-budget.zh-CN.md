# 质量反馈预算修复

2026-11-11。针对小预算 DROP 实验中四次优化请求的实际诊断：`measuredFeedback.feedback` 全部为空，`truncated=true`。逐题质量反馈未送达优化器；接口修复仍通过独立的 `contractRepair` 收到具体路径和诊断。

## 原因

原打包器先构造一个候选的全部选中题目和轨迹，再检查60000字符总预算；首个候选超限时直接结束循环。原文、重复结果和轨迹可使首条反馈超限，之后较小的接口错误记录也被一并省略。候选省略ID列表本身还可能超过总预算。

## 改动

- 先为候选保留完整/阶段分数、配对变化、用量和最近的公开接口诊断。
- 再按剩余额度分配逐题细节；优先保留带证据的案例，必要时省略轨迹或缩短原文，原文摘要仍保留问题所在的尾部。
- 单个候选过大时继续处理后续候选。原文、结果和轨迹的省略保持可见。
- 总字符预算覆盖整个反馈包及省略ID元数据；省略候选总数与被截断的ID列表分别记录。
- 原生和旧声明式搜索的简要历史均增加被质量淘汰候选的 `stageScore`，同时保留阶段大小，避免将部分测量混同完整候选得分。
- 反馈格式标记为 `public-field-whitelist-v3`。保持公开字段白名单，参考答案、私有评分错误、隐藏断言和凭据不进入反馈。

优化器system、节点system、模型配置、评分、固定数据划分、候选选择概率、阶段淘汰阈值和预算均保持原设置。此修复没有插入新的求解节点或自动修改业务答案。

## 验证

新增四项回归在旧实现全部复现失败，修复后通过，覆盖超长真实结构、6000字符紧预算、800个历史候选的省略元数据，以及两条搜索入口中下一轮可见的阶段分数。

类型检查通过，完整回归408/408通过、零跳过，包含已安装的Automation模拟环境。HTTP模拟测试使用固定的provider Python虚拟环境，127.0.0.1/localhost绕过本机代理；不向真实模型发请求。
